## Investigated and confirmed blocked (11 sources)

`revenue_department`, `finance_department`, `education`, `industries_mines`,
`legal_department`, `legislative_parliamentary`, `agri_cooperation`,
`social_justice`, `narmada_water`, `gad_nri`, `women_child_deeper`,
`rural_dev` (12 total).

Diagnosis, confirmed per-site:
1. Plain `requests` GET returns 200 with an empty page shell — these sites'
   GR/document listings are rendered client-side via JS/AJAX after page load,
   not present in the static HTML.
2. Using Playwright (a real browser) to execute that JS instead triggers each
   site's WAF, which detects headless-browser fingerprints and returns either
   a math CAPTCHA ("Security check... enter the above result") or a hard
   block ("Web Page Blocked, Attack ID: 20000021", flagging the requesting IP).
3. Re-confirmed plain `requests` is *not* blocked on these same domains
   immediately after (e.g. `legal.gujarat.gov.in`, `panchayat.gujarat.gov.in`
   both returned normal 200s with no CAPTCHA via `requests` right after the
   Playwright probe) — so this is specifically anti-headless-browser
   detection, not a general IP block.

**Getting past this would require solving a CAPTCHA or evading
headless-browser detection — both are circumventing a deliberate anti-bot
control, and neither was attempted.** All 12 written to their `_status.json`
as `blocked` with this reasoning. No PDFs were pulled for these sources.
